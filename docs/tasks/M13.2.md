# M13.2 — Recovery runbook decision

M13.2 defines a read-only decision record for incidents. It does not change mode,
retry a provider, or perform any transaction action; an operator applies the
runbook manually.

## Input/output

Input fields are `incident_id`, `data_status`, `provider_status`, `state_known`,
and `retry_count`. Status values are `OK`, `STALE`, `MISSING`, `ERROR`, or
`UNKNOWN`.

```json
{
  "incident_id": "inc-1",
  "data_status": "STALE",
  "provider_status": "OK",
  "state_known": true,
  "retry_count": 0
}
```

Output `action` is `NO_ACTION`, `PAUSE_ENTRIES`, or `ESCALATE`; it includes the
incident, reason codes, and a UTC timestamp. `ESCALATE` has priority when state is
unknown or any status is invalid. `PAUSE_ENTRIES` is fail-closed for stale/missing
data or provider errors. `NO_ACTION` requires all statuses `OK` and known state.

Acceptance: each priority path, invalid input, deterministic reason, and read-only
behavior is tested. This is a runbook aid, not a production-readiness claim.
