# M11.3 — Laporan kualitas sinyal

## Kontrak input

`build_quality_report` menerima satu laporan dengan periode timezone-aware dan
daftar hasil M11.2. `sample_count` adalah jumlah seluruh sinyal pada periode;
setiap record yang tersedia memiliki `signal_id` unik, timestamp ISO-8601, dan
status M11.2. Status `MATCH` dan `DEVIATION` adalah outcome valid. Status
`INSUFFICIENT_DATA` tetap dicatat tetapi bukan outcome valid.

```json
{
  "report_id": "quality-2026-01",
  "started_at": "2026-01-01T00:00:00Z",
  "ended_at": "2026-01-31T23:59:59Z",
  "outcomes": [
    {"signal_id": "s-001", "status": "MATCH", "timestamp": "2026-01-02T00:00:00Z"},
    {"signal_id": "s-002", "status": "DEVIATION", "timestamp": "2026-01-03T00:00:00Z"}
  ],
  "sample_count": 2,
  "valid_sample_count": 2,
  "metrics": {"drawdown": null, "expectancy": null},
  "probability_data": null
}
```

`valid_sample_count` boleh diberikan untuk audit input; jika diberikan harus
sama dengan jumlah status valid yang dihitung dari `outcomes`. `metrics` dan
`probability_data` bersifat opsional. Probabilitas hanya dianggap tersedia jika
semua syarat berikut benar: minimal sample terpenuhi, `out_of_sample` true,
`calibrated` true, dan setiap nilai berada pada rentang 0–1. Selain itu output
memakai `probability_available: false` dan tidak menampilkan probabilitas
prediktif; gunakan ringkasan `score`/`evidence_quality` bila disediakan.

## Kontrak output

```json
{
  "report_id": "quality-2026-01",
  "status": "INCONCLUSIVE",
  "sample_count": 2,
  "valid_sample_count": 2,
  "match_count": 1,
  "deviation_count": 1,
  "deviation_ratio": 0.5,
  "data_coverage": 1.0,
  "drawdown": null,
  "expectancy": null,
  "calibration_summary": null,
  "probability_available": false,
  "limitations": ["sample valid di bawah minimum 30", "drawdown tidak tersedia", "expectancy tidak tersedia"],
  "generated_at": "2026-02-01T00:00:00Z"
}
```

Aturan deterministik:

- `MIN_VALID_SAMPLE` default 30 dan dapat dikonfigurasi.
- `INSUFFICIENT_DATA` jika tidak ada outcome valid.
- `INCONCLUSIVE` jika outcome valid ada tetapi kurang dari minimum.
- `VALID` hanya jika minimum terpenuhi, semua record tervalidasi, dan metrik dapat dihitung.
- `deviation_ratio = deviation_count / valid_sample_count` dan
  `data_coverage = valid_sample_count / sample_count`; pembagian nol tidak dilakukan.
- Rasio dibulatkan ke 6 tempat desimal dengan ROUND_HALF_UP.
- Periode/timestamp harus timezone-aware, `started_at <= ended_at`, dan setiap
  record berada dalam periode. ID duplikat, timestamp rusak, label tak dikenal,
  sample count negatif, atau `valid_sample_count` tidak konsisten menyebabkan
  validasi gagal (`ValueError`), bukan angka sintetis.
- `drawdown`/`expectancy` yang tidak tersedia menjadi `null` dan alasannya masuk
  `limitations`.
- `generated_at` selalu UTC timezone-aware.
