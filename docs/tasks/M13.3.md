# M13.3 — Signal Bot monitoring snapshot

M13.3 produces a deterministic health report for operators. It observes state but
does not send alerts, change controls, or claim production readiness.

## Contract

Inputs: `snapshot_status` (`FRESH`, `PARTIAL`, `STALE`, `MISSING`, `INVALID`),
`provider_ok`, `telegram_ok`, `audit_ok`, and optional `observed_at`/`now`.
The default freshness limit is 120 seconds, inherited from M12.1 and configurable.

Output:

```json
{"status":"DEGRADED","alerts":["SNAPSHOT_STALE"],"generated_at":"2026-09-21T00:00:00Z"}
```

`HEALTHY` requires fresh snapshot, healthy provider and Telegram, and a passing
audit. `DEGRADED` covers partial/stale data or a provider/Telegram outage.
`CRITICAL` covers missing/invalid snapshot, invalid timestamps, or a failed audit.
Alerts are stable reason codes; the caller decides how to notify an operator.

Acceptance: boundary freshness, each severity, invalid input, configurable limit,
and read-only/no-execution behavior are tested. Fixture health data is not live
provider evidence; this milestone does not establish production readiness.
