# M13.1 — Signal-only operational audit gate

M13.1 is a pre-operation checklist, not a production-readiness claim. It proves
that the configured runtime is one of the accepted Signal Bot modes and that the
execution boundary remains disabled before a run may emit signals.

## Input and output

`audit_signal_only(settings, data_ready, allowlist_ready)` returns a deterministic
`AuditReport`:

```json
{
  "status": "PASS",
  "checks": {"mode": "PASS", "execution_boundary": "PASS", "data": "PASS", "allowlist": "PASS"},
  "reasons": [],
  "generated_at": "2026-09-21T00:00:00Z"
}
```

`status` is `PASS` only when every check passes; otherwise it is `FAIL`. A failed
data or allowlist check must fail closed. The report is an audit artifact only and
does not call a provider or alter runtime configuration.

## Checks

- `mode`: settings mode is `collect_only`, `replay`, or `paper_signal`.
- `execution_boundary`: the existing execution boundary reports `DISABLED`.
- `data`: required input/feed checks are ready.
- `allowlist`: the Telegram private allowlist is configured for the run.

Acceptance: all-pass and each individual failure are tested; no signing, wallet,
or transaction path is introduced; the full suite passes before merge.
