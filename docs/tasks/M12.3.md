# M12.3 — Social Evidence and Bounded LLM Narrative

Status: contract established; implementation must remain read-only and optional.

## Scope

M12.3 adds a bounded narrative enrichment layer for Signal Bot. Social inputs are
fixtures or explicitly supplied evidence only; no production social provider is
enabled. The deterministic strategy remains the sole signal gate. Narrative output
may explain an accepted signal but can never create one, veto one, or claim a
calibrated probability.

## Input

Each request contains one `SocialEvidence` record:

```json
{
  "mint_address": "9abc...",
  "source": "fixture",
  "source_id": "fixture-001",
  "published_at": "2026-09-21T10:00:00Z",
  "received_at": "2026-09-21T10:00:01Z",
  "text": "Example evidence used for tests only.",
  "data_status": "AVAILABLE"
}
```

`data_status` is one of `AVAILABLE`, `MISSING`, `STALE`, `INVALID`, or
`DUPLICATE`. Missing, stale, invalid, and duplicate evidence is never sent to a
provider. Fixture data must be labelled `source: fixture` and is never reported as
live social analysis.

## Output

```json
{
  "mint_address": "9abc...",
  "status": "AVAILABLE",
  "narrative_summary": "...",
  "catalyst_status": "unknown",
  "evidence_refs": ["fixture-001"],
  "uncertainties": [],
  "generated_at": "2026-09-21T10:00:02Z",
  "expires_at": "2026-09-21T10:15:02Z",
  "prompt_version": "m12.3-v1",
  "probability_available": false,
  "reason": null
}
```

`status` is `AVAILABLE`, `CACHE_HIT`, `DISABLED`, or `UNAVAILABLE`. Unavailable
narratives use `narrative_summary: null`; they do not change deterministic signal
eligibility. `probability_available` is always false in M12.3.

## Bounds, cache, and deduplication

- Input text is limited to 4,000 characters; provider output is limited to 2,000.
- Timeout defaults to 5 seconds and retries default to 1 (maximum 1 retry).
- Cache TTL defaults to 900 seconds. Cache keys include mint, model/prompt version,
  and an evidence hash. Expired or invalid evidence is not cached.
- Duplicate `(source, source_id)` evidence is rejected before any provider call.
- Provider responses must include bounded narrative fields and a known evidence
  reference. Unknown or oversized responses fall back to unavailable.

## Budget hard stop

Current configuration is `enabled: false` and monthly budget `Rp0`; this is a hard
stop and the provider must not be called. A future explicitly enabled configuration
may start at a documented ceiling of `Rp50.000/month`, with a call cap. Calls are
allowed only when both a finite pre-call cost estimate and a finite actual cost in
IDR are available. Unknown conversion, estimate, or actual cost fails closed. A
timeout, provider failure, or exhausted budget returns an unavailable narrative and
never blocks an otherwise valid deterministic signal.

## Acceptance criteria

1. No-provider and fixture-only modes are clearly marked non-live.
2. Disabled/Rp0 mode makes zero provider calls.
3. Cache hits, expiry, deduplication, timeout, retry limit, provider failure, budget
   exhaustion, unknown cost, and bounded output are deterministic and tested.
4. Narrative fallback preserves an eligible deterministic signal.
5. Runtime contains no wallet, signer, private key, or transaction submission path.
6. M12.3 tests and the complete project suite pass before commit, push, and merge.
