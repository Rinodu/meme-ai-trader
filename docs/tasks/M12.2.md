# M12.2 — Anomaly ablation read-only

## Batas dan prinsip

M12.2 hanya mengevaluasi filter pada snapshot `OnChainSnapshot` M12.1. Ia
tidak mengambil data masa depan, tidak mengubah snapshot, dan tidak memiliki
wallet, signer, keypair, atau jalur transaksi. Threshold adalah parameter
eksperimen yang harus dibekukan sebelum evaluasi; nilainya bukan klaim optimal
dan tidak dipilih setelah melihat hasil holdout.

## Aturan anomaly

`AnomalyRules` memiliki `rule_version` dan parameter berikut. Parameter `None`
menonaktifkan aturan tersebut; tidak ada default threshold live yang dibuat.

| Kode | Field sumber | Aturan/threshold | Satuan | Data yang diperlukan |
| --- | --- | --- | --- | --- |
| `ANOMALY_TOP_HOLDER_RATIO_HIGH` | `top_holder_ratio` | `value > max_top_holder_ratio` | fraksi 0–1 | nilai holder teratas yang fresh |
| `ANOMALY_LIQUIDITY_BELOW_THRESHOLD` | `liquidity` | `value < min_liquidity` | unit quote provider | likuiditas yang fresh |
| `ANOMALY_ACTIVE_MINT_AUTHORITY` | `mint_authority` | nilai tidak `null` jika `reject_active_authorities` true | boolean faktual | authority dari snapshot |
| `ANOMALY_ACTIVE_FREEZE_AUTHORITY` | `freeze_authority` | nilai tidak `null` jika `reject_active_authorities` true | boolean faktual | authority dari snapshot |
| `ANOMALY_LIQUIDITY_NOT_LOCKED` | `liquidity_locked` | `false` jika `require_liquidity_locked` true | boolean faktual | bukti lock yang dapat diverifikasi |

Missing/stale/invalid bukan anomaly. Jika snapshot M12.1 tidak
`allows_signal()`, keputusan ditolak dengan `DATA_NOT_READY`. Jika field yang
dibutuhkan aturan aktif hilang pada snapshot `PARTIAL`, keputusan ditolak
dengan `DATA_NOT_READY` dan field dicatat; jangan mengubahnya menjadi anomaly.

## Input dan keputusan filter

Setiap `CandidateObservation` berisi:

```json
{
  "candidate_id": "c-001",
  "decision_time": "2026-09-21T12:00:00Z",
  "snapshot": {"...": "schema M12.1"},
  "baseline_eligible": true,
  "outcome": "TP_FIRST",
  "cost": "1.25"
}
```

`outcome` adalah label `Outcome` yang sudah tersedia (`TP_FIRST`, `SL_FIRST`,
`TIMEOUT`, `EXIT_UNAVAILABLE`, `DATA_INSUFFICIENT`) dan hanya dipakai setelah
keputusan untuk evaluasi; filter tidak boleh membacanya. `cost` adalah biaya
simulator yang sudah dihitung dengan asumsi sama untuk kedua mode.

`evaluate_candidate` menghasilkan `candidate_id`, waktu observasi, versi aturan,
status data, `passed`, `reasons`, dan `anomaly_codes`. Kode alasan data adalah
`DATA_NOT_READY`, `DATA_LEAKAGE`, atau `BASELINE_INELIGIBLE`; kode anomaly hanya
kode `ANOMALY_*` di tabel. Snapshot dengan `observed_at > decision_time` selalu
`DATA_LEAKAGE` dan ditolak.

## Ablation baseline vs filter

`evaluate_ablation` menjalankan dua mode pada daftar kandidat, periode, rule
outcome, dan cost assumption yang sama:

- **baseline**: `baseline_eligible` dan gate `OnChainSnapshot.allows_signal()`;
- **baseline_plus_filter**: kandidat baseline yang lolos `evaluate_candidate`.

Kedua mode memakai denominator yang sama (`candidate_count`) dan tidak melihat
outcome saat memilih kandidat. Output mencakup jumlah kandidat, signal count,
coverage (`signal_count / candidate_count`), penolakan per alasan, jumlah label
valid, `TP_FIRST` ratio sebagai observasi berdenominator jelas, total/average
cost, serta `outcomes_lost_to_filter` berisi ID dan label kandidat yang lolos
baseline tetapi ditolak filter.

Status laporan menggunakan konvensi M11:

- `INSUFFICIENT_DATA`: tidak ada kandidat atau tidak ada sinyal baseline;
- `INCONCLUSIVE`: data tersedia tetapi label baseline atau filter kurang dari
  `minimum_labeled` (default 30), atau salah satu mode tidak punya denominator
  metrik yang dapat dihitung;
- `VALID`: kedua mode memiliki label minimum dan metrik yang dapat dihitung.

Perubahan rasio `TP_FIRST` atau biaya hanyalah hasil observasi. Metrik pada
sinyal yang lolos filter rentan selection bias; laporan selalu memuat denominator
dan jumlah sampel kedua mode. Tidak ada klaim filter meningkatkan profit, win
rate, atau performa keseluruhan dari laporan `INCONCLUSIVE` maupun `VALID`.

## Acceptance criteria dan fixture

- Anomaly terdeteksi di atas threshold dan tidak terdeteksi tepat/di bawah threshold.
- Field anomaly hilang, snapshot `STALE`/`INVALID`/`MISSING`, dan future data
  menghasilkan alasan data terpisah serta tidak menghasilkan sinyal.
- Baseline dan baseline+filter memakai dataset, periode, outcome, dan biaya yang sama.
- Observasi dengan `observed_at` setelah `decision_time` ditolak sebagai leakage.
- Coverage, label, rasio `TP_FIRST`, biaya, penolakan per alasan, dan outcome
  yang hilang dihitung dengan denominator eksplisit.
- Sampel label di bawah 30 menghasilkan `INCONCLUSIVE`; tanpa baseline signal
  menghasilkan `INSUFFICIENT_DATA`.
- Guard no-signing/no-submit/no-private-key dan seluruh regresi milestone
  sebelumnya tetap lulus.
